# Fixed Preview Time 技术设计

## Why：问题与目标

谱面原始 flow、判定线动画、Note 控制事件和作者显隐共同决定 Note 何时进入视野，因此单纯设置一个全局 flow 不能保证一致的可见预判时间。已观察到的失败包括同一段谱面中部分 Note 明显晚出现，以及候选 flow 将原本在屏幕外的高速位移暴露成突然冲过视野。

本功能的目标是在不改变音频、谱面时间、判定窗口和成绩的前提下，让尽可能多的非 fake Note 从进入可视区域到判定的现实时间接近用户设置值。不能可靠认证的 Note 必须完整恢复原谱表现，而不是带着不完整的时间门继续运行。

## What：用户可见行为

- 功能默认关闭，位于“改版设置 → 改版玩法”，标注为实验性功能。
- 默认值为 `0.450s`，范围 `0.100–0.750s`，步进 `0.001s`。
- 暂停页支持单击微调与长按加速；暂停、变速、改值、视口和相关渲染参数变化都会重建缓存。
- 仅改变 Note 的视觉 flow 和首次显示时间；不改变音频、谱面、判定和成绩。
- 当前不实现动态或多段 flow；无法使用安全常量计划时回退原谱。

## 文中术语

- **flow**：项目原本用于控制 Note 沿判定线运动距离的视觉倍率。改变它会改变 Note 看起来移动多快、从哪里进入屏幕，但不会改变判定时间。
- **目标出现时刻**：按用户设置的预判秒数，从 Note 判定时刻向前推算出的时刻。例如目标为 `0.450s`，就希望 Note 最晚在判定前约 0.450 秒开始可见。
- **时间门**：本实现自己的叫法，表示“在目标出现时刻之前先不绘制这个 Note”。它只控制最早显示时间，不改变运动或判定。
- **作者显隐**：谱面自身设置的透明度、负 line alpha、`appear_before` 和 cover 等规则。这些是谱面表现的一部分，统一预判不会强行绕过。
- **计划（`PreviewPlan`）**：预先为单个 Note 算好的最终处理方式。播放时只读取它，不会每帧重新求解。
- **renderer**：项目中真正把 Note 提交到画面的生产绘制代码。求解器与它共享关键变换，避免两边对 Note 位置的理解不同。
- **viewport / NDC**：viewport 是当前实际可见区域；NDC 是与具体分辨率无关的标准化屏幕坐标，本文的运动速度阈值用这种坐标衡量。

## How：逐 Note 计划与求解

本实现只改变渲染，判定、音频、谱面时间、判定窗、成绩与原始速度事件不变。每个 Note 在进入播放或相关设置变化时取得一个计划；之后渲染只读取这个结果，不会在每一帧重复做复杂计算。

- **原运动已经合适（`GateOnly`）**：如果 Note 按谱面原来的 flow 就能从目标时刻一直安全显示到判定前，就不改它的运动，只在目标时刻之前隐藏。这样对原谱视觉的改动最小。
- **使用安全的固定流速（`Constant`）**：如果原运动不能满足目标，求解器会尝试找一个固定的 flow。只有它从目标时刻到判定前始终留在屏幕内、没有制造新的显隐问题、也没有突然高速移动时才会采用。
- **完全保留原谱（`Original`）**：如果前两种方式都不能证明安全，就不接管这个 Note。它继续使用原来的 flow 和原来的显隐，也不会套用新的时间门。fake Note 始终走这条路径。

选择顺序是：尽量不改运动，其次才寻找固定流速，最后安全回退。Hold 的 head/body/tail 使用同一份计划，避免三部分移动不一致。暂停、改速、改预判、视口变化或原 flow 变化时会丢弃旧结果并重算，防止设置改变后仍沿用旧速度。

首先检查原运动。如果目标时刻 Note 因谱面作者的规则仍应隐藏，就不能仅靠加时间门宣称成功；不过求解器仍会尝试新的固定 flow，因为在 `shorten_holds + hold_partial_cover` 等情况下，flow 会改变 Hold 的实际尾部位置，确实可能让 Note 合法出现。

通常求解器会先找出“能看到”和“看不到”之间的 flow 边界，再逐步缩小范围。这就是代码中的 **bracket（二分搜索的两端）**。但有些复杂动画并不随 flow 单调变化：两端都看不到，中间某一小段反而能看到。此时会把 flow 范围分成 64 段做便宜的目标时刻探测，寻找这种中间可见区间；文档和代码把它称为“可见岛”。

找到可能的中间区间后，不会因为“目标那一帧能看到”就直接采用。求解器最多挑选右缘、中点和左缘三个候选，逐个执行完整检查。如果一个较慢候选因突然移动失败、另一个较快候选因中途出屏失败，还会在两者之间最多尝试 8 个候选。所有候选使用相同的安全标准；找不到就回退 `Original`，不会放宽规则。

在普通情况下，求解器用二分搜索找出目标时刻仍可见的最大固定 flow，然后检查整段运动。如果最大候选后续会出屏，但最小 flow 能安全通过，就再向两者之间细化，尽量选择较大的安全值。这样既提高覆盖率，也保证搜索次数有上限。

每个 `Constant` 候选按现实时间最多每约 4.17ms 检查一次（240Hz），包含目标时刻、区间内部和判定前一瞬间。单个候选最多检查 1537 个点；超过预算就回退，避免异常谱面造成无界计算。如果候选和原谱都因作者设置而暂时隐藏，这一段不要求 Note 留在屏幕内；但如果候选自己制造了原谱没有的隐藏，就会被拒绝。采样验证有明确预算，但不能数学证明两个采样点之间绝无更短的异常。

`Constant` 还会检查相邻采样间 Note 头部在屏幕坐标中的移动速度，防止“虽然一直在屏幕里，但突然冲得很快”。通常使用 24 NDC/现实秒的绝对上限；只有原谱 Note 在相邻两帧本来就可见、且也在屏幕内时，候选才允许保留原谱已有的高速运动，并额外留出 1 NDC/现实秒作为浮点和采样误差。原谱当时若透明或在屏幕外，就不能拿那段不可见的高速位移给候选作免责。超过限制会以 `motion_spike` 原因回退 `Original`。

`GateOnly` 完全保留原谱运动，所以不会用新阈值否定谱面本来就存在的高速效果。Tap/Flick/Drag 用 Note 中心作为跟踪点；Hold 使用不受皮肤贴图偏移和 body/tail 长度影响的逻辑头部位置（代码中的 semantic head anchor）。目前运动保护只检查 Hold 头，只有 tail 独立发生的尖峰仍未覆盖。

`prpr/src/note_visual.rs` 把“Note 最终画在哪里”的共同计算集中起来，供求解器和真实 renderer 同时使用，包括 Note 的旋转、缩放、control size/pos、incline、flow，以及判定线旋转和平移。这样求解器不会再用一套简化公式、renderer 用另一套公式。求解器还分别检查 Hold 实际会绘制的 head/body/tail；反向且根本不会绘制的 body 不能用来假装 Hold 仍在屏幕里。

几何检查只回答“如果绘制，Note 是否连续留在屏幕内”；作者显隐检查再回答“谱面此刻是否允许绘制”。它使用和 renderer 相同的 Note alpha、control alpha、负 line alpha、`appear_before` 和 cover 数据，不会绕过谱面作者的设计。如果所有方案在目标时刻都被作者规则阻止，就以 `authored_visibility_at_target` 原因回退。回退原因会尽量保留真正的失败类别，避免把出屏或运动尖峰误报成透明度问题。

“作者显隐”有意不包括玩家 FADE_IN/FADE_OUT Mod、场景级 `res.alpha` 淡入、纹理透明像素、shader 或其他遮挡；这些瞬时或后处理状态不应固化进逐 Note 缓存。仍未共享的是生产绘制提交、纹理尺寸/UV 切片和最终 camera/postprocessing。noise-area、HUD 和按住 Hold 之后的可读性也不在区间几何验证内，因此设备体验仍是合并前的重要验证出口。

## Compatibility：兼容性与回滚

- 默认关闭时保留原来的 Note flow、作者显隐和渲染时序。
- 旧配置中的非有限值或超范围值会在加载时归一化，不需要迁移谱面、资源包或用户数据。
- fake Note 始终使用 `Original`；不能安全处理的普通 Note 也恢复原 flow 和原显隐。
- 缓存键包含启用状态、目标时间、播放倍率、视口、Note 宽度、翻转、练习视图、Hold 选项和当前原始 flow，避免跨设置复用旧计划。
- 实现不增加新的平台专用运行时依赖；功能可关闭，整个变更也可通过回滚恢复。

## Testing：已验证范围

- 73 项 Rust 测试覆盖配置归一化、三类视觉计划、Note/Hold 几何、作者显隐、cover、运动尖峰、暂停热更新、播放倍率、长按调节和设置分组。
- Android `aarch64-linux-android` 目标上的 `prpr` 编译检查通过；最终 ARM64 APK 已完成构建、签名与 16 KiB 对齐检查。
- 私有 15 谱四档预判矩阵及动态设置场景共 61 次运行，无引擎或视觉契约失败；总体支持覆盖率为 `95.874%`，其余 Note 安全回退 `Original`。
- 最终 APK 已随机试玩几张谱，存在少量可接受回退，未报告明显的新异常。

谱面语料和批量 renderer 审计工具不属于本 PR：语料不提交，审计基础设施保留在开发分支。仓库内的合成测试覆盖已发现的主要回归形状。

## Limitations：已知限制与讨论点

- `Constant` 使用 240Hz 现实时间采样和有限预算验证，不能数学证明采样间隔内绝无更短事件。
- 运动保护检查语义 Note 头锚点；Hold 仅 tail 独立发生的尖峰尚未覆盖。
- 不验证纹理透明像素、shader/postprocessing、HUD/粒子遮挡或按住 Hold 后的完整可读性。
- 部分谱面在较长预判时间下会有更多 Note 回退；当前选择安全回退，而不是放宽连续可见或运动约束。
- 动态或多段 flow 可能提升极端谱面的覆盖率，但会显著增加运行时状态和视觉连续性风险，本 PR 有意不实现。维护者可讨论是否值得作为后续功能。
